# 발표 장소 점검표

구성: 앱은 집의 Linux 서버에서 포트 8000으로 돈다. 외부 접속은 nginx(https 앞단 서버)가 받아 8000으로 넘긴다. AI는 학교 LLM만 쓰며, 집 서버가 호출하므로 발표 노트북에는 인증서가 필요 없다.

## 미리 알아 둘 위험

- 학교 LLM이 느리다. 번역 약 38초, 분석 약 57초가 걸렸다.
- Semantic Scholar(논문 정보 조회 서비스)가 429(요청 과다)로 막을 수 있다.
- 그래서 **분석과 번역은 발표 전날 데모 계정으로 미리 실행해 둔다.** 현장에서는 저장된 결과를 보여 주고, 새 호출은 번역 한 문장만 한다.

## 집 서버 쪽 (발표 전날 + 직전, 순서대로)

| 순서 | 확인 | 명령 | 기대 | 결과 |
|---|---|---|---|---|
| 1 | 앱 상태 | `curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/api/health` | 200 | |
| 2 | nginx 경유 | `curl -s -o /dev/null -w '%{http_code}\n' https://<공개 주소>/api/health` | 200 | |
| 3 | 운영 DB 접속 | 데모 계정으로 로그인 후 `curl -s -b cookie.txt https://<공개 주소>/api/papers \| head -c 200` | 논문 목록 JSON | |
| 4 | 학교 LLM | 번역 화면에서 한 문장 번역, 걸린 시간 측정 | 결과 본문, 약 40초 이내 | |
| 5 | 분석 결과 | 미리 돌린 분석이 논문 허브 분석 탭에 보이는지 | 결과 표시 | |

비밀값(쿠키, 키)은 화면과 기록에 남기지 않는다. `cookie.txt`는 확인 후 지운다.
