# 화면 확인 기록: 로그인·서재·설정

`archi-studio-ui-auth-library` change의 화면을 확인한 기록과, 자동 검사로 대신할 수 없어 사람이 손으로 확인할 항목이다.
자동 검사는 `scripts/ui-screens.mjs`(실행법은 `docs/dev/setup.md`의 "화면 검사" 절).

## 1. 스크린샷을 눈으로 본 결과 (2026-10-23)

나눔 글꼴을 설정한 Chromium으로 찍어 한글까지 보이는 상태에서 확인했다.

| 화면 | 본 것 | 결과 |
|---|---|---|
| 공통 부품(라이트) | 기본·보조·위험·비활성·진행 중 버튼, 오류 입력창의 빨간 테두리와 문구, 탭 밑줄, 상태 패널 세 종류, 스트리밍 오류 알림 | 색과 모양으로 상태가 구분된다 |
| 서재 1280px(라이트) | 왼쪽 메뉴(서재 강조, 나머지 "준비 중"), 가운데 목록 카드와 PDF·메모 표시, 오른쪽 설정 패널, 아래쪽 이메일·로그아웃 | 세 영역이 테두리로 나뉘고 겹침이 없다 |
| 서재 390px(다크) | 위쪽 메뉴·설정 버튼, 긴 제목이 줄바꿈되어 카드 안에 머묾, 삭제 버튼 위치 | 가로 넘침 없음, 다크 색이 적용된다 |
| 서재 오류 767px(다크) | 빨간 테두리 오류 패널과 다시 시도 버튼 | 오류가 강조되고 글자가 읽힌다 |
| 로그인 1280px(다크) | 가운데 카드, 기본 버튼(밝은 초록 바탕에 어두운 글자), 가입 링크 | 대비가 충분하다 |
| 설정 1280px(라이트) | 연결 상태 표, 위험 색 연결 해제 버튼, 메뉴 아래쪽 설정 항목 강조 | 현재 위치가 설정으로 표시된다 |

남은 것: 글꼴이 나눔 고정폭 계열로 잡혀 실제 사용자 화면(Pretendard 등)과 글자 모양이 다르다. 글꼴 차이로 줄바꿈 위치가 달라질 수 있으니
데모 전에 사용자 브라우저에서 한 번 더 본다.

## 2. 실제 서버로 확인한 것 (자동, `library-real` 묶음)

로컬 DB에 SQL로 사용자 한 명, 컬렉션 2개, 논문 55건을 넣고 실제 `/api/papers`, `/api/collections`로 확인했다.

- 첫 쪽 50건이 최근 동기화 순으로 나오고, 더 보기로 55건이 중복 없이 이어진다.
- `attention` 검색 6건, 컬렉션만 10건, 둘을 함께 쓰면 1건이다.

## 3. 손으로 확인할 것 (실제 Zotero 계정 필요)

Zotero OAuth와 Zotero 웹 API를 실제로 부르는 동작은 자동 검사에서 가짜 응답으로만 확인했다. 데모 계정으로 아래를 차례로 확인한다.

- [ ] 서재의 "Zotero 연결"을 누르면 Zotero 승인 화면으로 가고, 승인하면 `/library`로 돌아와 동기화 버튼이 보인다
- [ ] Zotero 승인 화면에서 거부하면 `/settings?zotero=denied`로 돌아와 오류 안내와 "Zotero 다시 연결" 버튼이 보인다
- [ ] 동기화를 누르면 "N건 추가, N건 갱신, N건 삭제"가 보이고 목록에 Zotero 논문이 나타난다
- [ ] 웹페이지 추가에 실제 기사 주소를 넣으면 목록 맨 위에 새 항목이 생기고 Zotero에도 항목이 생긴다
- [ ] 논문 삭제를 확인하면 목록에서 사라지고 Zotero에서는 휴지통으로 옮겨진다
- [ ] 설정의 연결 해제를 확인하면 "연결되어 있지 않습니다"로 바뀌고, 서재의 논문 목록은 그대로 남는다
