# Spec Delta

## Purpose

Archi Studio의 모든 화면이 올라타는 3단 레이아웃 셸과 통합 디자인 토큰을 정의한다. 개별 화면의 내용은 다루지 않고, 어떤 화면이든 같은 틀과 같은 값을 쓰게 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 3단 레이아웃 셸
시스템은 데스크톱 폭에서 왼쪽 메뉴, 가운데 작업 영역, 오른쪽 설정 패널의 세 영역을 한 화면에 보여줘야 한다(SHALL). 모든 화면은 가운데 작업 영역에 내용을 채운다.

#### Scenario: 데스크톱에서 세 영역 표시
- **WHEN** 사용자가 폭 1280px 이상의 브라우저에서 앱의 아무 화면이나 연다
- **THEN** 왼쪽 메뉴, 가운데 작업 영역, 오른쪽 설정 패널이 모두 보이고 작업 영역이 남는 폭을 차지한다

#### Scenario: 설정 패널이 필요 없는 화면
- **WHEN** 오른쪽 패널에 보여줄 내용이 없는 화면을 연다
- **THEN** 시스템은 오른쪽 패널을 접고 작업 영역이 그 폭을 이어받는다

### Requirement: 좁은 화면 대응
시스템은 폭 768px 미만에서 왼쪽 메뉴와 오른쪽 설정 패널을 기본으로 접어 가운데 작업 영역만 보여줘야 한다(SHALL). 접힌 패널은 버튼으로 열 수 있어야 하고, 열면 작업 영역 위에 겹쳐 보인다.

#### Scenario: 휴대폰 폭
- **WHEN** 사용자가 폭 390px 화면에서 앱을 연다
- **THEN** 작업 영역만 보이고 가로 스크롤이 생기지 않으며, 메뉴 버튼으로 왼쪽 메뉴를 열 수 있다

### Requirement: 통합 디자인 토큰
시스템은 색, 글자, 간격, 모서리, 그림자, 레이아웃 치수를 이름 있는 토큰으로 한 곳에서만 정의해야 한다(MUST). 셸과 화면은 토큰을 통해서만 이 값을 써야 하고, 같은 의미의 값을 화면마다 따로 적지 않는다.

#### Scenario: 토큰 한 곳 정의
- **WHEN** 토큰 정의 파일 밖의 스타일에서 색 값(`#` 또는 `rgb`)을 직접 쓴 곳을 검색한다
- **THEN** 셸이 만든 스타일에는 그런 곳이 없다

### Requirement: 라이트와 다크 테마
시스템은 기본적으로 사용자의 시스템 설정(밝게 또는 어둡게)을 따라야 한다(SHALL). 두 테마의 모든 토큰은 같은 이름으로 정의되어야 하고, 본문과 배경의 대비는 읽기에 충분해야 한다.

#### Scenario: 시스템이 다크 모드
- **WHEN** 사용자의 운영체제가 다크 모드이고 앱을 연다
- **THEN** 셸의 배경, 글자, 테두리가 다크 토큰 값으로 표시되고 라이트 값이 섞이지 않는다

#### Scenario: 토큰 누락 방지
- **WHEN** 라이트 테마에는 있지만 다크 테마에는 없는 토큰 이름이 있는지 비교한다
- **THEN** 그런 토큰은 없다

### Requirement: 벨루와 폴리오 값의 대응 기록
시스템은 통합 토큰이 벨루와 폴리오의 어떤 값에서 왔는지(또는 새로 정한 값인지) 문서로 남겨야 한다(SHALL). 한쪽 값을 버린 경우에는 버린 이유를 적는다.

#### Scenario: 대응표 확인
- **WHEN** 검토자가 디자인 토큰 대응 문서를 연다
- **THEN** 색, 글자, 간격, 모서리, 레이아웃 치수 각각에 대해 벨루 값, 폴리오 값, 채택한 값이 한 줄씩 있다
