# Spec Delta

## Purpose

번역 화면(`/translate`)에서 영어를 입력하고 한국어 번역이 글자 단위로 흘러나오는 것을 보는 흐름과, 중지·복사·논문 연결·이력·오류 상태에서 화면이 어떻게 반응하는지를 정의한다. API 계약은 `translation` 스펙이 정한다.

## ADDED Requirements

### Requirement: 번역 입력과 실행
시스템은 번역 화면에 원문 입력창과 입력한 글자 수(예: `12 / 5000`)를 보여줘야 한다(SHALL). 입력은 5000자를 넘지 못한다(MUST). 사용자는 번역 버튼 또는 Ctrl+Enter로 번역을 실행하고, 앞뒤 공백을 뺀 입력이 비어 있으면 번역 버튼이 비활성이다.

#### Scenario: 버튼으로 번역
- **WHEN** 사용자가 `attention is all you need`를 입력하고 번역 버튼을 누른다
- **THEN** 화면은 `POST /api/translate`를 `text` 하나로 호출하고 결과 영역에 번역문을 표시한다

#### Scenario: 단축키로 번역
- **WHEN** 입력창에 포커스가 있는 상태에서 Ctrl+Enter를 누른다
- **THEN** 번역 버튼을 누른 것과 같은 요청이 한 번만 보내진다

#### Scenario: 글자 수 상한
- **WHEN** 5000자가 이미 들어 있는 입력창에 글자를 더 붙여 넣는다
- **THEN** 입력은 5000자에서 잘리고 글자 수 표시는 `5000 / 5000`이다

#### Scenario: 빈 입력
- **WHEN** 입력창이 비어 있거나 공백뿐이다
- **THEN** 번역 버튼은 비활성이고 Ctrl+Enter를 눌러도 요청이 보내지지 않는다

### Requirement: 스트리밍 결과 표시
시스템은 번역문이 도착하는 대로 결과 영역에 이어 붙여 보여줘야 한다(SHALL). 번역하는 동안에는 깜빡이는 커서와 "번역 중" 상태를 보여주고, 복사 버튼은 번역이 끝날 때까지 비활성이다. 한글처럼 여러 바이트로 이루어진 글자가 청크 경계에서 쪼개져 도착해도 깨지지 않아야 한다(MUST).

#### Scenario: 도중 표시
- **WHEN** 서버가 번역문을 세 번에 나눠 흘려보내고 첫 번째 청크만 도착했다
- **THEN** 결과 영역에 첫 번째 청크의 글자가 보이고 커서가 깜빡이며 복사 버튼은 비활성이다

#### Scenario: 완료 후 복사
- **WHEN** 번역이 끝난 뒤 복사 버튼을 누른다
- **THEN** 번역문 전체가 클립보드에 들어가고 버튼이 잠시 "복사됨"으로 바뀐다

#### Scenario: 글자가 청크 경계에서 쪼개짐
- **WHEN** 세 바이트짜리 한글 글자의 첫 바이트와 나머지 바이트가 다른 청크로 도착한다
- **THEN** 결과 영역에는 깨진 글자 없이 온전한 글자가 표시된다

### Requirement: 중지와 새 요청
시스템은 번역 중에 중지 버튼과 Escape 키로 요청을 취소할 수 있게 해야 한다(SHALL). 취소하면 그때까지 받은 글자는 남기고 "중단됨"을 표시한다. 새 번역을 실행하면 진행 중이던 요청을 먼저 취소한다(MUST).

#### Scenario: 중지
- **WHEN** 번역이 흘러나오는 중에 중지 버튼을 누른다
- **THEN** 스트림 읽기가 중단되고 받은 글자는 남으며 "중단됨"이 표시된다
- **AND** 번역 버튼이 다시 활성이 된다

#### Scenario: 연속 실행
- **WHEN** 번역이 진행 중일 때 다른 문장으로 번역을 실행한다
- **THEN** 이전 요청은 취소되고 이전 문장의 글자는 새 결과에 섞이지 않는다

### Requirement: 오류 상태 표시
시스템은 번역 요청이 실패하면 입력을 지우지 않고 원인에 맞는 한국어 안내를 결과 영역에 보여줘야 한다(SHALL). 안내에 서버의 내부 문구나 스택을 그대로 보여주지 않는다(MUST).

#### Scenario: 세션 만료
- **WHEN** 번역 요청이 401 `unauthenticated`를 받는다
- **THEN** 결과 영역에 로그인이 필요하다는 안내와 로그인 화면 링크(`/login?redirect=<현재 주소>`)가 보이고, 화면은 자동으로 이동하지 않으며 입력은 그대로 남는다

#### Scenario: 서버 오류
- **WHEN** 번역 요청이 500 `internal_error` 또는 502 `ai_unavailable`을 받는다
- **THEN** 결과 영역에 일시적인 오류라는 안내와 "다시 시도" 버튼이 보이고, 누르면 같은 입력으로 다시 요청한다

#### Scenario: AI 미설정
- **WHEN** 번역 요청이 503 `ai_not_configured`를 받는다
- **THEN** 결과 영역에 관리자에게 문의하라는 안내가 보이고 "다시 시도" 버튼은 보이지 않는다

#### Scenario: 서버가 거부한 입력
- **WHEN** 번역 요청이 400 `invalid_request` 또는 413 `payload_too_large`를 받는다
- **THEN** 결과 영역에 입력을 확인하라는 안내가 보이고 "다시 시도" 버튼은 보이지 않는다

#### Scenario: 스트림이 중간에 끊김
- **WHEN** 번역문이 일부 도착한 뒤 연결이 끊긴다
- **THEN** 받은 글자는 남기고 번역이 완료되지 않았다는 안내와 "다시 시도" 버튼을 보여준다

### Requirement: 논문 연결
시스템은 주소의 선택 쿼리 `paperId`를 읽어 번역 요청에 함께 보내고, 연결된 논문의 제목을 번역 화면에 보여줘야 한다(SHALL). `paperId`가 없으면 논문과 무관하게 동작한다. 논문 제목은 `GET /api/papers/{id}`로 가져온다.

#### Scenario: 논문에 연결해 번역
- **WHEN** 사용자가 `/translate?paperId=<내 논문 id>`를 열고 문장을 번역한다
- **THEN** 화면 위쪽에 그 논문의 제목이 표시되고 번역 요청 본문에 `paperId`가 들어 있다

#### Scenario: 없는 논문
- **WHEN** 존재하지 않거나 남의 논문 `paperId`로 화면을 연다 (논문 조회가 404 `paper_not_found`)
- **THEN** 논문을 찾을 수 없다는 안내를 보여주고, 논문 연결 없이 번역을 계속하는 버튼을 제공한다
- **AND** 연결 없이 계속하면 이후 요청에 `paperId`를 보내지 않는다

### Requirement: 번역 이력
시스템은 번역 화면에서 `GET /api/translate/history`로 받은 최근 번역을 최신순으로 최대 20개 보여주고 더 보기로 나머지를 펼치게 해야 한다(SHALL). 이력 항목을 고르면 그 항목의 원문과 번역문을 입력창과 결과 영역에 채우되 번역 요청은 보내지 않는다(MUST). 논문이 연결된 화면에서는 이력 범위를 "이 논문만"으로 바꿀 수 있다.

#### Scenario: 이력 항목 선택
- **WHEN** 이력의 항목 하나를 누른다
- **THEN** 입력창에 그 항목의 원문이, 결과 영역에 번역문이 채워진다
- **AND** `POST /api/translate`는 호출되지 않는다

#### Scenario: 이력 없음
- **WHEN** 이력 응답의 `items`가 빈 배열이다
- **THEN** 이력 영역에 아직 번역한 기록이 없다는 안내가 보인다

#### Scenario: 이 논문만 보기
- **WHEN** 논문이 연결된 화면에서 이력 범위를 "이 논문만"으로 바꾼다
- **THEN** 화면은 `GET /api/translate/history?paperId=<id>`로 다시 조회해 그 논문의 번역만 보여준다

#### Scenario: 번역 직후 이력 갱신
- **WHEN** 번역이 정상으로 끝난다
- **THEN** 이력 목록 맨 위에 방금 번역이 나타난다

### Requirement: 번역 화면의 접근성
시스템은 결과 영역을 청크마다 스크린리더가 읽어 주게 하지 않고, 번역이 끝났을 때 "번역이 완료되었습니다"를 한 번 알려 줘야 한다(SHALL). 입력창, 버튼, 이력 항목은 키보드만으로 조작할 수 있어야 한다(MUST).

#### Scenario: 완료 안내
- **WHEN** 번역이 끝난다
- **THEN** 상태 알림 영역(`aria-live="polite"`)에 "번역이 완료되었습니다"가 한 번 나타나고, 흘러나오는 동안에는 결과 영역 자체가 알림을 반복하지 않는다

#### Scenario: 키보드 조작
- **WHEN** 사용자가 마우스 없이 Tab 키만으로 이동한다
- **THEN** 입력창, 번역·중지·복사 버튼, 이력 항목 순서로 포커스가 이동하고 포커스 표시가 보인다
