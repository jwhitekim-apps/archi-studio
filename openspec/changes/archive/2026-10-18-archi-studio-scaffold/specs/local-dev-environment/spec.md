# Spec Delta

## Purpose

개발자가 운영 DB를 건드리지 않고 이 서버에서 Archi Studio의 DB를 올리고, 초기화하고, 마이그레이션을 검증하는 방법을 정의한다. 무료 요금제 때문에 별도 클라우드 개발 프로젝트가 없어서 로컬 DB가 유일한 개발 DB다.

## ADDED Requirements

### Requirement: 명령으로 로컬 DB 시작과 종료
시스템은 개발자가 저장소 루트에서 명령 하나로 로컬 Supabase를 시작하고 다른 명령 하나로 멈출 수 있게 해야 한다(SHALL). 이 명령은 전역 설치 없이 저장소의 의존성만으로 동작해야 한다.

#### Scenario: 처음 시작
- **WHEN** 저장소를 새로 받은 개발자가 의존성을 설치하고 시작 명령을 실행한다
- **THEN** 로컬 DB와 인증 서비스가 올라오고, 접속 주소와 키가 터미널에 출력된다

#### Scenario: 포트 충돌
- **WHEN** 다른 프로세스가 로컬 Supabase가 쓸 포트를 이미 쓰고 있다
- **THEN** 시작은 어느 포트가 문제인지 알려주는 오류로 끝나고 기존 프로세스를 건드리지 않는다

### Requirement: 마이그레이션으로 스키마 재현
시스템은 마이그레이션 파일만으로 DB 스키마를 처음부터 재현할 수 있어야 한다(MUST). 초기화 명령은 로컬 DB를 지우고 모든 마이그레이션을 정해진 순서대로 다시 적용한다.

#### Scenario: 초기화 후 같은 상태
- **WHEN** 초기화 명령을 실행한다
- **THEN** 데이터 모델 문서의 테이블 11개가 모두 만들어지고, 마이그레이션 적용 오류는 없다

#### Scenario: 순서 보장
- **WHEN** 마이그레이션 파일 이름을 정렬해 순서대로 읽는다
- **THEN** 외래 키가 가리키는 테이블은 항상 그 테이블을 참조하는 테이블보다 먼저 만들어진다

### Requirement: 기존 벨루 테이블 불간섭
시스템은 마이그레이션이 기존 벨루 테이블(`users`, `sessions`, `paper_history`, `translation_history`, `arch_history`, `contextor_history`)을 수정하거나 참조하거나 지우지 않게 해야 한다(MUST). 새 테이블은 `if not exists` 없이 만들어서 이름이 겹치면 적용이 실패해야 한다.

#### Scenario: 기존 테이블 참조 검사
- **WHEN** 모든 마이그레이션 파일에서 기존 벨루 테이블 이름을 검색한다
- **THEN** 해당 테이블을 대상으로 한 `alter`, `drop`, `insert`, 외래 키 참조가 없다

#### Scenario: 이름 충돌
- **WHEN** 같은 이름의 테이블이 이미 있는 DB에 마이그레이션을 적용한다
- **THEN** 적용은 오류로 멈추고 어떤 테이블이 겹쳤는지 알려준다

### Requirement: 새 테이블의 접근 제한
시스템은 마이그레이션이 만드는 모든 새 테이블에 행 수준 보안(RLS)을 켜야 한다(SHALL). 정책은 두지 않고 서버가 서비스 키로 접속해 사용자 id로 거른다.

#### Scenario: RLS 확인
- **WHEN** 초기화한 로컬 DB에서 새 테이블의 RLS 상태를 조회한다
- **THEN** 11개 모두 RLS가 켜져 있다

### Requirement: 비밀값의 저장소 격리
시스템은 로컬 DB 접속 키와 환경 변수 파일을 저장소에 커밋하지 않게 해야 한다(MUST). 저장소에는 값 없이 변수 이름만 적은 예시 파일만 둔다.

#### Scenario: 예시 파일만 추적
- **WHEN** 저장소에서 추적되는 파일에 키 문자열이 있는지 검색한다
- **THEN** 실제 키는 없고 예시 파일에는 변수 이름만 있다
