# Spec Delta

## Purpose

모든 화면이 함께 쓰는 공통 UI 부품(버튼, 입력창, 상태 표시, 확인 대화상자, 스트리밍 출력 영역 등)의 동작 계약을 정의한다. 화면마다 같은 일을 다르게 구현하지 않고, 키보드와 스크린리더로도 같은 방식으로 쓰이게 하는 것이 목적이다.

## ADDED Requirements

### Requirement: 토큰만 쓰는 부품
시스템의 공통 UI 부품은 색, 글자, 간격, 모서리, 그림자를 디자인 토큰으로만 지정해야 한다(MUST). 부품 스타일에는 색 값(`#hex`, `rgb()`)을 직접 쓰지 않는다.

#### Scenario: 직접 색 지정 검색
- **WHEN** 공통 부품 폴더의 스타일에서 `#` 색 값과 `rgb(`를 검색한다
- **THEN** 일치하는 곳이 없다

#### Scenario: 다크 테마
- **WHEN** 운영체제가 다크 모드인 상태에서 부품을 표시한다
- **THEN** 부품의 배경, 글자, 테두리가 다크 토큰 값으로 표시되고 본문 글자와 배경의 대비는 4.5:1 이상이다

### Requirement: 버튼과 입력창의 상태
시스템의 버튼과 입력창은 기본, 키보드 포커스, 비활성, 진행 중, 오류 상태를 시각적으로 구분해 보여줘야 한다(SHALL). 진행 중인 버튼은 같은 동작을 다시 실행할 수 없어야 하고, 입력창의 오류는 입력창과 연결된 문구로 알려야 한다.

#### Scenario: 진행 중 중복 실행 방지
- **WHEN** 진행 중 표시가 된 버튼을 한 번 더 누르거나 Enter를 친다
- **THEN** 같은 요청이 한 번 더 시작되지 않는다

#### Scenario: 키보드 포커스 표시
- **WHEN** 사용자가 Tab 키로 버튼이나 입력창에 이동한다
- **THEN** 포커스 모양이 토큰으로 정의된 색의 윤곽선으로 눈에 보인다

#### Scenario: 입력 오류 연결
- **WHEN** 입력창에 오류 문구를 지정한다
- **THEN** 오류 문구가 화면에 보이고 입력창이 그 문구를 설명으로 가리킨다(`aria-describedby`와 `aria-invalid`)

### Requirement: 로딩, 빈 상태, 오류 표시
시스템은 불러오는 중, 내용 없음, 오류를 같은 모양의 상태 패널로 보여줘야 한다(SHALL). 오류 패널은 즉시 읽히는 알림(`role="alert"`)이고, 나머지는 정중한 상태 안내(`role="status"`)다. 패널에는 다음 행동을 위한 버튼을 하나 넣을 수 있다.

#### Scenario: 오류 패널
- **WHEN** 상태 패널을 오류 종류로 표시한다
- **THEN** 스크린리더가 즉시 읽는 알림으로 표시되고 다시 시도 같은 버튼을 함께 보여줄 수 있다

#### Scenario: 빈 상태
- **WHEN** 목록이 비어 있어 빈 상태 패널을 표시한다
- **THEN** 무엇이 비어 있는지와 다음에 할 일을 한두 문장으로 보여준다

### Requirement: 확인 대화상자
시스템은 되돌리기 어려운 동작(삭제, 연결 해제)을 하기 전에 확인 대화상자를 거치게 해야 한다(SHALL). 대화상자가 열리면 포커스가 대화상자 안으로 들어가고, 닫으면 연 버튼으로 돌아온다. Escape는 취소다.

#### Scenario: 취소
- **WHEN** 확인 대화상자에서 Escape를 누른다
- **THEN** 대화상자가 닫히고 동작은 실행되지 않으며 포커스가 연 버튼으로 돌아온다

#### Scenario: 열린 동안의 배경
- **WHEN** 확인 대화상자가 열려 있다
- **THEN** 대화상자 밖의 요소는 Tab 키로 이동할 수 없다

### Requirement: 스트리밍 출력 영역
시스템은 글자가 나오는 대로 이어 붙여 보여주는 출력 영역을 제공해야 한다(SHALL). 영역은 도착한 순서대로 글자를 이어 붙이고, 진행 중임을 알리며, 스크린리더에는 정중한 갱신(`aria-live="polite"`)으로 전달한다. 도중에 오류가 나도 이미 받은 글자는 지우지 않고 오류를 따로 알린다.

#### Scenario: 글자가 순서대로 이어짐
- **WHEN** 출력 영역에 조각 "안녕", "하세요"가 차례로 도착한다
- **THEN** 영역에는 "안녕하세요"가 표시되고 진행 중 표시가 켜져 있다

#### Scenario: 완료
- **WHEN** 스트림이 끝났다고 알려 준다
- **THEN** 진행 중 표시가 꺼지고 받은 글자는 그대로 남는다

#### Scenario: 도중 오류
- **WHEN** 글자 일부를 받은 뒤 오류가 난다
- **THEN** 받은 글자는 그대로 남고 오류 알림이 영역 아래에 표시된다

### Requirement: 사이드바 메뉴 항목
시스템은 사이드바 메뉴 항목을 링크로 만들고, 현재 보고 있는 화면의 항목에 현재 위치 표시(`aria-current="page"`)와 시각적 강조를 해야 한다(SHALL). 아직 화면이 없는 항목은 눌러도 이동하지 않는 비활성으로 보여준다.

#### Scenario: 현재 화면 표시
- **WHEN** 사용자가 서재 화면을 연다
- **THEN** 메뉴의 '서재' 항목만 현재 위치로 표시된다

#### Scenario: 화면이 없는 항목
- **WHEN** 아직 구현되지 않은 메뉴 항목을 누른다
- **THEN** 화면 이동이 일어나지 않고 항목은 비활성으로 표시되어 있다
