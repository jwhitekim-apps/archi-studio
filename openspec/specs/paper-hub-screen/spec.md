# paper-hub-screen Specification

## Purpose

논문 하나의 허브 화면이 사용자에게 보여 주고 지켜야 하는 동작을 정의한다. 한 화면에서 원문을 읽고 메모를 쓰며 번역·분석 화면으로 넘어가는 흐름이 대상이고, 서버 계약은 `papers`와 `paper-notes` 스펙이 맡는다.

## Requirements


### Requirement: 허브 화면 열기
시스템은 `/papers/{id}` 주소로 들어오면 `GET /api/papers/{id}`로 논문 상세를 불러와 제목과 원문, 메모를 보여줘야 한다(SHALL). 불러오는 동안에는 로딩 표시를 보여준다.

#### Scenario: 정상 열기
- **WHEN** 사용자가 자기 논문의 `/papers/{id}` 주소를 연다
- **THEN** 화면은 논문 제목과 원문, 메모 영역을 보여준다

#### Scenario: 없는 논문
- **WHEN** 서버가 404 `paper_not_found`를 돌려준다
- **THEN** 화면은 "논문을 찾을 수 없습니다" 안내와 서재로 돌아가는 링크를 보여주고 원문과 메모 영역은 그리지 않는다

#### Scenario: 서버 오류
- **WHEN** 상세 조회가 네트워크 오류나 500으로 실패한다
- **THEN** 화면은 오류 안내와 "다시 시도" 버튼을 보여주고, 버튼을 누르면 상세를 다시 불러온다

### Requirement: 원문 보기
시스템은 논문의 첨부 종류가 `pdf`이면 `GET /api/papers/{id}/file`의 PDF를 페이지 단위로 그려 보여주고, `html`이면 격리된 프레임에 보여줘야 한다(SHALL). 첨부가 없으면 빈 상태 안내를 보여준다.

#### Scenario: PDF 첨부
- **WHEN** 첨부 종류가 `pdf`인 논문을 연다
- **THEN** 화면은 PDF 첫 페이지부터 세로로 이어서 보여주고 스크롤하면 다음 페이지가 나온다

#### Scenario: HTML 스냅샷 첨부
- **WHEN** 첨부 종류가 `html`인 논문을 연다
- **THEN** 화면은 그 문서를 스크립트가 실행되지 않는 격리된 프레임에 보여준다

#### Scenario: 첨부 없음
- **WHEN** 첨부가 없는 논문을 연다
- **THEN** 화면은 "원문이 없습니다" 안내를 보여주고 메모는 그대로 쓸 수 있다

### Requirement: 확대와 축소
시스템은 원문을 처음에 패널 폭에 맞춰 보여주고, 사용자가 확대·축소 버튼, Ctrl 또는 Cmd를 누른 휠, 두 손가락 벌리기로 배율을 바꿀 수 있게 해야 한다(SHALL). 확대한 지점이 화면에서 움직이지 않아야 한다.

#### Scenario: 폭 맞춤 기본값
- **WHEN** PDF를 처음 연다
- **THEN** 페이지 폭이 원문 패널 폭에 맞고 가로 스크롤이 없다

#### Scenario: 원래 크기로 되돌리기
- **WHEN** 배율을 바꾼 뒤 배율 표시 버튼을 누른다
- **THEN** 배율이 폭 맞춤 상태로 돌아간다

#### Scenario: 터치 확대
- **WHEN** 터치 화면에서 두 손가락을 벌린다
- **THEN** 두 손가락의 중심 지점을 기준으로 확대되고 페이지가 갑자기 튀지 않는다

### Requirement: 원문 텍스트 선택과 복사
시스템은 PDF의 글자를 마우스나 터치로 선택해 복사할 수 있어야 한다(SHALL). 선택한 글자가 화면에 그려진 글자와 겹쳐 보이도록 위치가 맞아야 한다.

#### Scenario: 문장 복사
- **WHEN** 사용자가 PDF의 문장을 드래그로 선택하고 복사한다
- **THEN** 클립보드에 그 문장이 들어가고 선택 영역은 그 문장과 겹쳐 보인다

### Requirement: 메모 자동 저장
시스템은 메모를 입력하면 마지막 입력 후 약 0.9초 뒤에 `PUT /api/papers/{id}/memo`로 한 번 저장해야 한다(SHALL). 입력이 이어지는 동안에는 저장 요청을 보내지 않고, 저장 상태("저장 중", "모두 저장됨", "저장하지 못함")를 화면에 표시한다.

#### Scenario: 입력 후 저장
- **WHEN** 사용자가 메모를 입력하고 1초 동안 멈춘다
- **THEN** 저장 요청이 한 번 가고 상태 표시가 "저장 중"에서 "모두 저장됨"으로 바뀐다

#### Scenario: 연속 입력
- **WHEN** 사용자가 0.5초 간격으로 계속 입력한다
- **THEN** 입력이 멈출 때까지 저장 요청은 가지 않는다

#### Scenario: 메모 불러오기
- **WHEN** 메모가 저장된 논문을 연다
- **THEN** `GET /api/papers/{id}/memo`의 본문이 편집 영역에 채워진다

### Requirement: 메모 저장 실패와 초안 보관
시스템은 저장이 성공하기 전의 내용을 브라우저에 임시 보관(초안)하고, 저장에 실패해도 입력한 내용을 잃지 않게 해야 한다(MUST). 저장에 성공하면 초안을 지운다.

#### Scenario: Zotero 미연결
- **WHEN** 저장 요청이 409 `zotero_not_connected`를 받는다
- **THEN** 화면은 "Zotero를 연결해야 저장할 수 있습니다" 안내를 보여주고 입력한 내용은 편집 영역에 남는다

#### Scenario: 너무 큰 메모
- **WHEN** 저장 요청이 413 `payload_too_large`를 받는다
- **THEN** 화면은 메모가 너무 길어 저장하지 못했다고 안내하고 내용은 지우지 않는다

#### Scenario: 네트워크 실패 뒤 복구
- **WHEN** 저장이 네트워크 오류로 실패한 뒤 사용자가 "다시 시도"를 누르고 서버가 성공을 돌려준다
- **THEN** 상태 표시가 "모두 저장됨"이 되고 임시 보관한 초안은 지워진다

#### Scenario: 다른 논문으로 갔다가 돌아옴
- **WHEN** 저장 전의 메모가 있는 채로 다른 논문을 열었다가 돌아온다
- **THEN** 편집 영역에는 저장 전 내용이 그대로 복원된다

### Requirement: 메모 미리보기의 안전
시스템은 마크다운 메모의 미리보기를 보여주되, 메모에 스크립트나 이벤트 속성 같은 실행 가능한 HTML이 들어 있어도 앱 안에서 실행되지 않게 해야 한다(MUST).

#### Scenario: 스크립트가 든 메모
- **WHEN** 메모에 `<script>`나 `onerror` 속성이 있는 HTML을 넣고 미리보기를 연다
- **THEN** 그 코드는 실행되지 않고 일반 글자나 제거된 모양으로 보인다

#### Scenario: 일반 마크다운
- **WHEN** 제목, 목록, 링크, 코드 블록이 든 메모의 미리보기를 연다
- **THEN** 각각 서식에 맞게 보인다

### Requirement: 넓은 화면과 좁은 화면 배치
시스템은 작업 영역(셸의 가운데 칸) 폭이 700px 이상이면 원문과 메모를 좌우로 나눠 함께 보여주고 둘 사이 구분선을 끌어 폭을 바꿀 수 있게 해야 한다(SHALL). 700px 미만이면 원문을 두고 메모를 아래에서 끌어올리는 시트로 보여준다. 메모 폭은 320px 이상이고 원문은 최소 360px을 지킨다.

#### Scenario: 넓은 화면
- **WHEN** 브라우저 폭 1280px(작업 영역 약 720px)에서 논문을 연다
- **THEN** 원문과 메모가 좌우에 함께 보이고 구분선을 끌어도 메모 폭은 320px 아래로, 원문 폭은 360px 아래로 내려가지 않는다

#### Scenario: 좁은 화면
- **WHEN** 브라우저 폭 390px에서 논문을 연다
- **THEN** 원문이 작업 영역을 차지하고 메모는 아래 손잡이로 접혀 있으며, 손잡이를 누르면 시트가 올라온다

#### Scenario: 창 크기를 바꾸면
- **WHEN** 열어 둔 상태에서 작업 영역 폭이 700px 밑으로 줄어든다
- **THEN** 좌우 분할이 시트로 바뀌고 입력 중이던 메모 내용과 원문의 확대 배율은 그대로 유지된다

#### Scenario: 시트의 키보드 접근
- **WHEN** 키보드로 시트를 열고 Escape를 누른다
- **THEN** 시트가 닫히고 포커스가 시트를 연 손잡이로 돌아온다

### Requirement: 번역과 분석으로 이동
시스템은 허브에 이 논문의 번역 화면과 분석 화면으로 가는 버튼을 보여주고, 각 버튼에 이 논문에 연결된 번역·분석 개수(`translationCount`, `analysisCount`)를 표시해야 한다(SHALL). 두 버튼은 논문 id를 주소 쿼리 `paperId`로 넘긴다.

#### Scenario: 개수 표시
- **WHEN** 번역 3개와 분석 1개가 연결된 논문을 연다
- **THEN** 번역 버튼에 3, 분석 버튼에 1이 보인다

#### Scenario: 이동
- **WHEN** 번역 버튼을 누른다
- **THEN** 주소가 `/translate?paperId={id}`로 바뀐다
