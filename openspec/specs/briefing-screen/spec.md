# briefing-screen Specification

## Purpose
비서(morning-desk)가 하루 한 번 만들어 저장한 브리핑을 앱 안에서 읽는 화면(Archi Log)의 동작을 정한다. 목록과 상세, 빈 상태와 오류 상태, 바깥에서 온 글을 안전하게 보여 주는 규칙을 다루고, 브리핑 데이터를 만드는 일과 API 계약은 다루지 않는다.

## Requirements

### Requirement: 브리핑 목록 화면
시스템은 `/log`에서 로그인한 사용자의 브리핑을 최신순으로 보여줘야 한다(SHALL). 각 항목은 날짜와 요약을 보여 주고, 누르면 그 브리핑의 상세 화면으로 이동한다. 서버가 `nextCursor`를 돌려주는 동안에는 "더 보기"로 다음 묶음을 이어서 불러온다.

#### Scenario: 브리핑이 쌓인 사용자가 목록을 연다
- **WHEN** 브리핑이 있는 사용자가 `/log`를 연다
- **THEN** 최신 날짜가 맨 위에 오는 목록이 날짜와 요약과 함께 보이고, 항목을 누르면 `/log/{브리핑 id}`로 이동한다

#### Scenario: 더 오래된 브리핑 이어 불러오기
- **WHEN** 응답에 `nextCursor`가 있어 "더 보기"가 보이는 상태에서 그 버튼을 누른다
- **THEN** 이미 보이는 항목 아래에 다음 묶음이 이어서 붙고, 마지막 묶음이면 "더 보기"가 사라진다

### Requirement: 브리핑 상세 화면
시스템은 `/log/{id}`에서 브리핑의 날짜, 요약, 본문 전체를 보여줘야 한다(SHALL). 브리핑이 언급한 논문이 있으면 논문 제목을 링크로 보여 주고, 누르면 `/papers/{논문 id}`로 이동한다. 목록으로 돌아가는 링크도 둔다.

#### Scenario: 논문이 언급된 브리핑
- **WHEN** 논문 2편을 언급한 브리핑의 상세를 연다
- **THEN** 본문 아래에 논문 2편의 제목 링크가 보이고, 각 링크는 `/papers/{그 논문의 id}`를 가리킨다

#### Scenario: 논문 제목을 불러오지 못한 경우
- **WHEN** 언급된 논문 하나의 제목을 불러오지 못한다
- **THEN** 브리핑 본문은 그대로 보이고, 그 논문은 제목 대신 "제목을 불러오지 못한 논문"이라는 링크로 표시된다

#### Scenario: 논문 언급이 없는 브리핑
- **WHEN** 언급된 논문이 없는 브리핑의 상세를 연다
- **THEN** 논문 링크 영역은 나타나지 않는다

### Requirement: 본문은 글자 그대로 표시
시스템은 브리핑의 요약과 본문을 HTML로 해석하지 않고 글자 그대로 보여줘야 한다(MUST). 본문의 줄바꿈은 유지한다. 브리핑에는 메일이나 GitHub 제목처럼 바깥에서 온 글이 섞일 수 있기 때문이다.

#### Scenario: 본문에 태그가 들어 있는 경우
- **WHEN** 본문에 `<script>alert(1)</script>` 같은 글자가 들어 있는 브리핑의 상세를 연다
- **THEN** 그 글자가 그대로 화면에 보이고 스크립트는 실행되지 않으며 화면 구조도 바뀌지 않는다

#### Scenario: 긴 줄과 줄바꿈
- **WHEN** 줄바꿈이 있고 공백 없는 아주 긴 주소가 들어 있는 본문을 폭 390px 화면에서 연다
- **THEN** 줄바꿈은 유지되고 긴 주소는 화면 안에서 줄을 바꿔 가로 스크롤이 생기지 않는다

### Requirement: 빈 상태
시스템은 브리핑이 하나도 없을 때 목록 자리에 빈 상태 안내를 보여줘야 한다(SHALL). 안내는 오류처럼 보이지 않고, 브리핑을 비서가 하루 한 번 만든다는 사실을 알려 준다.

#### Scenario: 브리핑이 아직 없는 사용자
- **WHEN** 브리핑이 하나도 없는 사용자가 `/log`를 연다
- **THEN** 빈 목록 대신 "아직 브리핑이 없어요" 같은 안내가 보이고 "더 보기" 버튼은 보이지 않는다

### Requirement: 오류와 불러오는 중 상태
시스템은 불러오는 동안 진행 표시를, 불러오지 못했을 때 원인에 맞는 안내를 보여줘야 한다(SHALL). 서버 오류나 연결 실패에는 다시 시도 버튼을 둔다. 없는 브리핑 주소에는 "찾을 수 없음"과 목록으로 가는 링크를 보여 준다. 상태 안내는 보조 기기(스크린리더)에도 전달되어야 한다.

#### Scenario: 서버 오류
- **WHEN** 목록 요청이 500을 돌려준다
- **THEN** 오류 안내와 "다시 시도" 버튼이 보이고, 버튼을 누르면 같은 요청을 다시 보낸다

#### Scenario: 없는 브리핑
- **WHEN** 존재하지 않거나 다른 사용자의 브리핑 id로 `/log/{id}`를 연다
- **THEN** 서버의 404에 맞춰 "찾을 수 없음" 안내와 `/log`로 가는 링크가 보이고, 다른 사용자의 브리핑이 존재하는지는 드러나지 않는다

#### Scenario: 불러오는 중
- **WHEN** 응답이 오기 전에 목록이나 상세를 연다
- **THEN** 진행 표시가 보이고 그 상태가 보조 기기에 알려진다

### Requirement: 로그인이 필요한 상태에서 열기
시스템은 로그인하지 않은 사용자가 `/log`나 `/log/{id}`를 열면 로그인 화면으로 보내고, 로그인에 성공하면 원래 열려던 주소로 돌려보내야 한다(SHALL). 카톡 알림의 링크가 이 흐름으로 열린다.

#### Scenario: 카톡 링크를 로그아웃 상태에서 연다
- **WHEN** 로그인하지 않은 브라우저에서 `/log/{id}` 주소를 연다
- **THEN** 로그인 화면이 보이고, 로그인에 성공하면 같은 `/log/{id}` 상세 화면이 열린다

#### Scenario: 세션이 중간에 만료된 경우
- **WHEN** 목록을 보던 중 "더 보기" 요청이 401을 돌려준다
- **THEN** 이미 보이던 항목을 지우지 않은 채 로그인이 필요하다는 안내와 로그인 이동이 나타난다

### Requirement: 읽기 전용 화면과 셸 연동
시스템은 이 화면에 브리핑을 만들거나 고치거나 지우는 조작을 두지 않아야 한다(MUST). 왼쪽 메뉴의 "브리핑" 항목은 `/log`를 가리키고 열려 있는 동안 현재 위치로 표시되며, 오른쪽 설정 패널은 접힌다.

#### Scenario: 메뉴에서 브리핑으로 이동
- **WHEN** 사용자가 왼쪽 메뉴의 "브리핑"을 누른다
- **THEN** `/log`가 열리고 메뉴에서 "브리핑"이 현재 위치로 표시되며 오른쪽 패널은 접혀 있다

#### Scenario: 쓰기 조작 없음
- **WHEN** 목록과 상세 화면에서 버튼과 입력창을 모두 찾는다
- **THEN** 브리핑을 추가, 수정, 삭제하는 조작은 없다
